# TomatoTogether - 陪伴式番茄钟

> 朋友之间的小圈子番茄钟应用，轻量、实时、温暖

---

## 1. 项目概述

### 1.1 背景与目标
TomatoTogether 是一个面向紧密好友圈子的陪伴式番茄钟应用。用户可以在房间内同步开启番茄、相互跟随、保持「有人在」的存在感，同时管理自己的 WIP 待办和项目统计。

### 1.2 核心理念
- **轻量优先**：SQLite + SSE + 轻量前端，占用资源少
- **前后解耦**：RESTful API 设计，文档完备，支持第三方轻量客户端接入
- **陪伴感**：不强调竞争，强调「一起」的感觉
- **隐私可控**：WIP 默认本地存储，云同步 opt-in
- **三层访问**：公开 → 房间成员 → 持久化用户，按需授权

### 1.3 目标用户
- 好友之间约定一起学习/工作的小圈子
- 需要「他人在场感」来提升专注动力的用户

### 1.4 三层访问设计

```
┌─────────────────────────────────────────────────────────────────┐
│  L1 公开                                                         │
│  ├── 加入房间（匿名）                                            │
│  ├── 获取房间信息                                               │
│  ├── 获取房间统计（汇总）                                        │
│  └── SSE 旁观（只读事件流）                                      │
├─────────────────────────────────────────────────────────────────┤
│  L2 房间成员（需要房间 token）                                   │
│  ├── 离开房间                                                   │
│  ├── 番茄操作（开始/跟随/结束）                                  │
│  ├── 用户列表 + 实时状态                                         │
│  ├── 状态更新（emoji + 消息）                                    │
│  ├── 公告接收                                                   │
│  └── SSE 完全访问（含写操作事件）                                │
├─────────────────────────────────────────────────────────────────┤
│  L3 持久化用户（需要注册账号）                                   │
│  ├── 账号注册 / 登录                                            │
│  ├── 项目 CRUD                                                  │
│  ├── WIP 云同步（创建/更新/删除/拉取）                          │
│  └── 个人统计数据                                                │
└─────────────────────────────────────────────────────────────────┘
```

### 2.4 数据库迁移

使用 [golang-migrate](https://github.com/golang-migrate/migrate) 进行数据库版本管理。

**迁移文件位置**：`backend/migrations/`

**命名规范**：
- 上线迁移：`{version}_{description}.up.sql`
- 回滚迁移：`{version}_{description}.down.sql`
- version 格式：6 位数字，如 `000001`、`000002`

**示例**：
```
backend/migrations/
├── 000001_create_users_table.up.sql
├── 000001_create_users_table.down.sql
├── 000002_create_rooms_table.up.sql
└── 000002_create_rooms_table.down.sql
```

## 4. 功能模块

### 4.1 番茄时间同步机制

番茄进行状态由**客户端本地维护**，服务端仅记录关键时间戳：

| 字段 | 用途 | 说明 |
|------|------|------|
| `started_at` | 服务端记录开始时间 | 用于计算服务端视角的 elapsed |
| `planned_duration` | 计划总时长 | 不变的值 |
| `remaining_seconds` | 客户端计算 | `planned_duration - elapsed` |

**同步流程**：
1. 客户端开始番茄时，记录本地 `startTime`
2. 客户端每秒更新：`remaining = planned - (now - startTime)`
3. SSE tick 每 5 秒推送一次 `remaining_seconds`，用于多端同步
4. 客户端收到 tick 后校准本地计时（容忍 ±2 秒偏差）

**偏差容忍策略**：
- 客户端与服务端时间偏差在 ±2 秒内，信任客户端
- 超过 ±2 秒，使用服务端 tick 值覆盖客户端

### 4.2 房间系统

#### 4.2.1 创建房间（L3）
- 输入：房间名、房间密码（可选）、是否只读
- 验证：房间名唯一
- 逻辑：创建房间 + 创建者自动成为房主（`is_owner=true`）
- 返回：房间信息
- **前提**：创建者必须是持久化用户（L3）

#### 4.2.2 加入房间（L1）
- 输入：房间名、用户名、房间密码（如有）
- 验证：房间存在、密码正确、用户未加入其他房间
- 逻辑：创建匿名用户或登录已有用户，加入房间
- 返回：房间 token（用于 L2 操作）
- **房主规则**：
  - 如果房间当前没有房主（所有人都离开了），加入的持久化用户自动成为房主
  - **房主必须是持久化用户**（有密码的 L3 用户）
  - 匿名用户无法成为房主，需要先设置密码升级为持久化用户
- **多设备支持**：
  - 匿名用户：同一设备 + 同 username = 同会话；不同设备视为独立用户
  - 持久化用户：每个设备独立 RoomToken，支持同时在线

#### 4.2.3 匿名用户与持久化用户

| 类型 | 说明 | 成为房主 |
|------|------|----------|
| 匿名用户 | 无密码的用户，仅限当前房间使用 | ❌ |
| 持久化用户 | 有密码的用户，可跨设备登录 | ✅ |

**匿名用户升级为持久化用户**：
1. 用户设置密码（通过 L3 接口）
2. 系统将其转换为持久化用户
3. 保留原有的 `username` 和房间 token

#### 4.2.4 房间权限（房主设置）
| 设置项 | 说明 |
|--------|------|
| 只读模式 | 加入后只能观看，不能开始番茄 |
| 需要密码 | 加入需房间密码 |

#### 4.2.5 房间管理员
- 房主也是普通成员，只是多了管理权限
- 房主可以设置/取消其他成员为房主
- 房主离开房间后不会删除房间，也不会转让权限
- 房主离开后 `is_owner` 标记保留，回来后仍是房主
- 房间可以没有房主存在（所有房主都离开后），此时第一个加入的持久化用户自动成为房主

#### 4.2.6 离开房间（L2）
- 用户主动离开，房间保留
- 如果离开的是最后一个用户，房间数据保留（支持「大家都去睡觉」的场景）
- 离开时清除该用户的 RoomToken
- 如果离开的是房主，`is_owner` 标记保留，用户回来后仍是房主

#### 4.2.7 旁观者模式（L1）
- 任何人都可以通过房间名加入旁观
- 只能接收 SSE 事件，不能发起任何操作
- 不占用房间成员名额

#### 4.2.8 Heartbeat 机制（防手滑退出）

为防止用户「手滑退出」导致番茄中断，引入心跳机制：

| 参数 | 值 | 说明 |
|------|-----|------|
| 客户端发送间隔 | 30 秒 | SSE ping 事件 |
| 服务端超时 | 2 分钟 | 无响应视为离线 |

**流程**：
1. 客户端连接 SSE 后，每 30 秒发送一次 `ping` 事件
2. 服务端收到 ping 后更新 `last_heartbeat`
3. 后台任务每 1 分钟检查所有 RoomToken
4. 如果 `last_heartbeat` 超过 2 分钟，更新用户状态为离线
5. 用户重新连接后，自动恢复之前的番茄状态

**恢复逻辑**：
- 用户重连时，服务端返回当前房间状态
- 客户端根据 `started_at` 和 `planned_duration` 计算剩余时间
- 番茄继续进行，不中断

### 4.3 番茄系统

#### 4.3.1 独立番茄（L2）
- 用户点击开始，选择关联项目（可选）和 WIP（可选）
- 用户自定义番茄参数（专注时长、休息时长等）
- 计时结束后记录 `PomodoroSession`
- 支持提前结束（会提醒跟随者）

#### 4.3.2 跟随番茄（L2）
- 用户选择跟随房间内某个正在番茄的用户
- 跟随者与主导者**完全同步**：番茄开始、结束、休息时长、休息开始时间均同步
- 所有时间由客户端本地计算，服务端提供 `started_at` 和 `planned_duration`
- 跟随者的 session 标记 `is_followed=true`
- 跟随者可以随时取消跟随，切换为独立计时
- 跟随者跟随不同的人，各自独立

**同步机制**：
- 主导者开始番茄 → 发送 `pomodoro_started` 事件（包含所有番茄参数）
- 跟随者收到事件后，使用主导者的番茄参数进行本地计时
- 主导者结束番茄时发送 `pomodoro_ended` 事件，包含 `rest_duration`
- 跟随者进入休息阶段，休息时长由主导者决定
- SSE tick 每 5 秒推送一次，用于纠正客户端时间偏差（±2秒容忍）

#### 4.3.3 跟随中断处理（L2）
- 当**主导者**提前结束番茄：
  - 跟随者收到浏览器通知 + SSE 事件（`leader_aborted`）
  - 跟随者进入「决策等待」状态
  - **所有决策都在番茄结束后的休息时间再做**：
    - 选择「继续独立计时」：从剩余时间继续
    - 选择「结束」：放弃当前番茄
- 当**跟随者**离开房间：
  - **不通知任何其他人**
  - 仅移除自己的跟随状态，切换为独立计时或空闲

#### 4.3.4 L2 Token 过期策略
- Token 有效期 24 小时
- 过期后用户降级为 L1（旁观者）
- 降级后：
  - SSE 连接降级为只读模式
  - 无法进行任何 L2 操作
  - 番茄状态保留
- 恢复方式：重新 join 房间获取新 token

#### 4.3.5 通知系统（L2）
- 番茄结束：浏览器通知
- 跟随中断：浏览器通知（hold 到休息阶段发送）
- 房主公告：浏览器通知（hold 到休息阶段）
- 通知合并：同类型通知可以合并（如「3 个番茄完成」）

### 4.4 状态系统

#### 4.4.1 用户状态（L2）
- 独立于番茄存在
- 格式：emoji + 一句话（最多 50 字符）
- 同房间可见
- 不存在跨房间状态

#### 4.4.2 状态预设（可选）
- 🧑‍💻 工作中
- ☕ 休息中
- 🍽 吃饭中
- 📚 学习中
- 🎮 游戏中

### 4.5 WIP 待办系统

#### 4.5.1 本地存储（默认）
- WIP 存储在 LocalStorage
- 纯客户端操作，无需网络
- 支持 TODO / WIP / DONE 三态

#### 4.5.2 云同步（L3，可选）
- 用户 opt-in 注册账号后可开启云同步
- 支持批量同步（首次开启时）
- 跨设备同步 WIP 和项目
- **Client_id 规则**：客户端生成 UUID v4，存储到云端
- **冲突处理**：以 `created_at` 最早的服务端记录为准

#### 4.5.3 状态流转
```
TODO → WIP → DONE
 ↑______|
（可以从 DONE 改回 TODO，此时 completed_at 清空）
```

### 4.6 项目系统（L3）

#### 4.6.1 CRUD 操作
| 操作 | 说明 |
|------|------|
| 创建 | 项目名 |
| 读取 | 仅自己可见 |
| 更新 | 修改项目名 |
| 删除 | 项目下的 WIP 变为「杂项工作」 |

#### 4.6.2 项目统计
- 按项目汇总番茄时长
- 杂项工作（未分类）始终存在，不可删除

### 4.7 统计系统

#### 4.7.1 个人统计（L3）
- 按项目汇总番茄时长
- 近 N 天的番茄次数/时长趋势
- 统计仅自己可见

#### 4.7.2 房间统计（L1）
- 房间内所有人的今日总番茄时长
- 不展示具体个人数据

## 5. API 设计

详见 [API.md](./API.md)

### 5.1 设计原则
- RESTful 风格
- API 正交，避免冗余
- 统一错误格式：`{ "error": "message" }`

### 5.2 层级认证
- L1：无认证（公开）
- L2：`Authorization: Bearer <room_token>`，有效期 24 小时，断线可重连
- L3：`Authorization: Bearer <access_token>`，有效期 1 小时，配合 refresh_token 续期

### 5.3 Token 设计

#### L2 房间 Token（RoomToken）
- 格式：UUID v4（服务端生成）
- 有效期：24 小时
- 存储：`room_tokens` 表
- 用途：标识用户在特定房间的会话
- 续期：重新 join 房间即可刷新
- 断连处理：服务端保留用户状态，断连后 2 分钟内重连可恢复
- **多设备支持**：
  - 同一设备重新 join：生成新 token，旧 token 失效
  - 不同设备独立 token：互不影响

#### L3 用户 Token（JWT）
- Access Token 有效期：1 小时
- Refresh Token 有效期：30 天
- 用途：用户身份认证、云端数据同步
- 续期：使用 refresh_token 换取新的 access_token

### 8.1 术语表

| 术语 | 说明 |
|------|------|
| L1/L2/L3 | 三个访问层级：公开、房间成员、持久化用户 |
| 主导者 | 发起番茄 session 的用户 |
| 跟随者 | 跟随主导者番茄的用户 |
| WIP | Work In Progress，正在进行的工作 |
| SSE | Server-Sent Events，服务端推送 |
| opt-in | 用户主动选择加入 |
| RoomToken | 用于 L2 认证的 Token，存储在 `room_tokens` 表 |
| client_id | 客户端生成的 UUID，用于 WIP 云同步映射 |
| Session 参数 | 番茄开始时由主导者设定，包括 `planned_duration`、`rest_duration`、`long_break_duration`、`sessions_before_long_break` |

### 8.2 番茄参数

| 参数 | 默认值 | 可配置 | 说明 |
|------|--------|--------|------|
| 专注时长 | 25 分钟 | 是 | `planned_duration`（秒） |
| 短休息时长 | 5 分钟 | 是 | `rest_duration`（秒） |
| 长休息时长 | 15 分钟 | 是 | `long_break_duration`（秒） |
| 长休息间隔 | 4 个番茄 | 是 | `sessions_before_long_break` |

**主导者决定所有番茄参数**，跟随者完全同步。

### 8.3 心跳参数

| 参数 | 值 | 说明 |
|------|-----|------|
| SSE tick 间隔 | 5 秒 | 状态同步 |
| 客户端 ping 间隔 | 30 秒 | 心跳保活 |
| 服务端超时 | 2 分钟 | 视为离线 |
